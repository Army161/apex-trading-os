Openbot is an open-source AI co-worker platform from Copilot Kit, and the timing is what makes it interesting. In the last few months, every big AI lab shipped its own version of the same idea. XAI has Grockbot, Meta has Muse, Open AI has Dots, and Anthropic has Clawed Duet. All four are agents that get their own computer in the cloud, sign into your apps, and keep working after you close the window. Openbot is the same shape, except you run it yourself on your own servers, and the repo has already passed 10,000 stars on GitHub. Grockbot came first. It's an early beta from XAI built together with Cursor and all the bots on one account share a single cloud computer. They sign into your tools the way a person would. They can learn a workflow by watching you do it and they can pass work to each other in group threads. Pricing starts around $120 a seat per month through cursor plans and it's included in the $300 Super Grock heavy plan. MetaMuse went the consumer route. It runs on Meta's Muse Spark model inside a dedicated cloud VM. You can chat with it in WhatsApp and it books things, shops, and sends emails. Meta did put real work into safety here. A separate agent called Sentinel watches everything Muse does before it reaches the internet. And Muse never sees your passwords. There's a free tier, then 20 and $100 plans, and it's limited to the US and Canada for now. Open AAI Dots runs on GPT6 Astra. Each dot has its own cloud computer and browser, connects to over 4,000 apps, and you can message it from Slack or Teams. Every one of these four lives on someone else's cloud. your login, your files, your company data, all sitting on a machine you don't control. You can't pick the model. You can't change how permissions work. For one person, that's fine. For a company with a security team, that's usually where the pilot quietly dies. Openbot runs on your own infrastructure instead, and it's a template, not a product. There's no hosted version and no signup page. You clone the repo, swap in your own bots and skills, and bring it up with Docker. The data sits in your own Postgress database. No model ships in the box either. An admin adds the API key and that key is encrypted and never logged. It's MIT licensed and it's still beta, so expect rough edges. Each bot gets a real computer, not a simulated one. a container with its own Chromium browser, its own login, its own files, and only the tools you allow. By default, each person gets one container with a separate folder and browser profile for each of their bots. And if you tick the isolated option on a bot, it gets a whole container to itself. So, a login one bot holds can't be picked up by the next bot. Compare that to Grockbot where every bot on the account shares the same box. Every action also passes through one gateway. Opening a page, typing into a form, writing a file, calling an outside tool, running a shell command. The gateway checks it against your policy, writes an audit row, and only then lets it run. The record exists before the action happens, not after. And there's no side path that skips it. The rules use CEL which is Google's common expression language. You can write a rule against the bot, the person, the website, the exact element being clicked, the shell command, and even what started the run. So you could let a person do something, but block a scheduled routine from doing the exact same thing. Deny rules get checked first. No policy means nothing is allowed and if a rule is broken, it refuses instead of opening up. Most automation tools fail the other way around. Unlike Duet, you can watch the work live. The bot screen sits right next to the chat, and under it, there's an activity list showing every command it ran, every file it saved, and the output. When the bot hits a login wall or a two-factor prompt, it asks for help. You take the wheel in the same panel, finish that step, and hand it back. While you're driving, the bot's actions get refused, not queued up. Passwords never land in the transcript either. The log only records that a secret was asked for and how long it was. The framework is your choice, too. A bot in OpenBot is just any endpoint that speaks AGUI. That's the open protocol copilot kit wrote for how an agent talks to the screen a person is looking at. MCP handles tools. A2A handles agents talking to each other. AGUI handles the human side. So an agent built in Langraph, Mastra, Crew AI, Pidantic AI, Google ADK or plain handwritten code all plug in the same way and each one gets its own channel. With Dots, you get GPT. With Duet, you get Claude. Here you pick the model and the stack. Out of the box, you get two bots, general assistant and knowledge. A third one, risk analyst, shows up once its endpoint is configured, and 10 more examples sit in the catalog folder. One checks expense claims against the actual written policy. One turns meeting notes into real follow-ups. Others write release notes from what shipped, triage tickets, answer new hire questions from the handbook, hand over on call shifts, and group customer feedback into themes. Bots are just config files, so you copy one in, write your own, or create one from the bots page. The homepage looks a lot like chat GPT once it's running. It greets you by name, and there's a single ask anything box. Openbot picks the right bot for you, or you type the at sign to choose one yourself. The left side has bots, capabilities, connections, and browser. The bots page splits into yours and shared with you so a company can publish bots for everyone while people keep their own private ones. The admin area is grouped by plain questions. What bots can reach covers credentials, boundaries, approvals, and computers. What bots can do covers plugins, skills, automatic learning, UI components, and a playground. Who can get in covers people and identity providers and what happened is the audit trail. That audit trail is readable, not a raw log file. It lists what was allowed, what was refused, and what failed. And every refusal names the exact rule that blocked it. So when a bot suddenly stops doing something, you know why in a few seconds. Google Drive, Notion, and a few web research tools ship builtin, and Composio adds a few hundred more apps behind one account. Each one runs as the person asking, not as some shared admin. On the knowledge side, a bot connected to Drive or One Drive only sees files the person asking could already open. If permissions are unclear, it returns nothing instead of guessing, and answers come with their sources attached. Skills are just instructions you call with a slash in the chat box. There's even a skill that helps you write new skills, but it only saves when you press the button. Routines let a bot work on a schedule with a 15minute minimum gap and a cap of 20 active ones. If a routine fails 10 times in a row, it switches itself off so it doesn't burn your model budget overnight. You can also carry a conversation over to Slack, Teams, or Text Message, which is the same reach DOTs and Duet advertise. SignIn works with Google, Microsoft, or Octa, or your company's own SAML or OIDC provider routed by email domain. A fresh install runs in single user mode where every request is one admin. Fine on a laptop, but you turn it off before anyone else gets access. Setup is short. You need Docker Bun, a model key, and a CopilotKit intelligence project. Copy the envle file. Run bun install. Log in with the copilot kit command line and run the setup learning script. Add your open AI key and run start.sh. That brings up the database, the API on port 301, the routine worker, and the app on port 3010, then checks each one is healthy. For a real server, there's a single Docker image and a Helm chart. One honest catch though, intelligence is required. Threads and memory live there and the server won't start without it. There's a free developer plan and it can be self-hosted, but OpenBot isn't fully standalone. Copilot Kit also built Open Do It on top of Openbot. It's an open-source take on Claude Duet with morning briefs, inbox triage, and an approval step before it sends, pays, signs, or deletes anything. Their site lists open muse and open dots, too. So, every time a big lab ships a closed agent, an open template now shows up that does the same job on your own hardware. Grockbot, Muse, Dots, and Duet are products you rent. OpenBot is a starting point you own. It's rougher. It needs a developer to set up, and it's still beta. But for a company that wants AI co-workers without handing its login to someone else's cloud, it's the closest thing to that right now.
